HOW TO USE THIS RUBRIC
--------------------------------------------------------------------------------
- Section point totals (1=15, 2=15, 3=15, 4=25, 5=10, 6=10, 7=10) match the
  assignment prompt exactly.
- Part A (Presentation & Reproducibility) is scored as DEDUCTIONS from the
  earned section total, capped at -15 points overall. The hard caps in A1
  (non-running notebook) apply on top of that cap.
- Within each section, every row lists the criterion, its point value, and what
  full / partial / no credit looks like. Partial credit is assessed per row.
- An attempted-but-flawed answer always scores higher than a skipped one. A
  section left blank earns 0; the same section attempted badly earns something.
- Grading is done on a fresh kernel: "Restart & Run All," against the
  instructor's own OPRA.PILLAR pull for the announced date range (per Section
  1.1, students buy their own copy of the same window, so the grader's copy is
  substitutable for the student's, column-for-column) read in via the path
  variable near the top of the notebook. Do not expect, and do not penalize
  the absence of, the student's raw Databento files in the submission -- per
  the prompt's licensing note, those must NOT be redistributed; only the
  notebook and its (student-local) cache are expected.
- Because every student's exact strikes/expirations/contracts differ (chosen
  from their own first/last day's chain per Section 1.2), grade the underlying
  METHOD at each step, not specific numeric answers.

PART A -- PRESENTATION & REPRODUCIBILITY  (cross-cutting; deductions, max -15)
================================================================================

A1. NOTEBOOK RUNS TOP-TO-BOTTOM WITHOUT ERROR
    - Clean run against a same-format OPRA panel, no errors: no deduction.
    - Runs with harmless warnings only (brentq convergence chatter, pandas
      dtype notices that don't change results): no deduction.
    - One or two cells raise errors but the rest of the notebook is
      independent and gradeable: -5, and the failing section(s) are graded on
      their visible saved output only.
    - Notebook errors early and large portions cannot execute: FINAL SCORE
      CAPPED AT 60% of otherwise-earned points.
    - Not submitted as a single .ipynb (PDF only, .py only, bare Colab link
      with no notebook file): not accepted for full credit; see syllabus
      format/late policy.

A2. SELF-CONTAINED AND REPRODUCIBLE (within the licensing constraint)
    - Raw OPRA data is read from a path set in a single variable near the top
      of the notebook (not hard-coded inline, not an absolute path that only
      exists on the student's own machine); the caching pipeline (Section 1.4)
      is implemented in code, not hand-run once and pasted in as numbers; a
      grader with their own same-format panel at that path can run the
      notebook end to end: no deduction.
    - Path variable exists but other hard-coded absolute paths remain
      elsewhere in the notebook: -3.
    - No path variable; raw data location hard-coded inline in multiple
      places: -5.
    - Random seeds are set (or results are shown to be stable without them)
      for the Section 4.1 GBM simulation: -2 if missing AND results are
      visibly seed-sensitive.
    - Raw Databento files, or a derived cache built from them, are included in
      the submission in violation of the prompt's licensing note: flag for
      the instructor; not itself a numeric deduction but must be addressed
      before any grade is finalized.

A3. SECTION HEADINGS AND NAVIGATION
    - Every section and subsection from the prompt appears as a markdown
      header, in order, labeled so it is immediately obvious which question is
      being answered (e.g. "## Section 4.2 - Real Lifecycle Hedge"): no
      deduction.
    - Headers present but some sub-parts are buried in code comments or not
      clearly delineated: -3.
    - No markdown structure; grader has to hunt for where each answer is: -6.

A4. FIGURES
    - All plots render inline after a clean run: no deduction.
    - Titles, axis labels, and legends (the smile plot by expiration, the
      hedging P&L distribution, the cost/frequency tradeoff plot, etc.) are
      present on every figure: up to -5 total, scaled to how many plots are
      unlabeled. Per the prompt, unlabeled plots do not receive full credit.
    - Figures illegible (smile plotted with no moneyness/strike axis label, a
      P&L histogram with no marked real-path outcome, default styling that
      hides the point being made): -2.

A5. WRITTEN INTERPRETATION QUALITY
    - Prose cells actually answer what was asked, cite specific numbers and
      figures (dollar mispricings, implied vols, P&L means/stds -- not just
      "it's different"), and are in the student's own words: no deduction.
    - Interpretation is vague, generic, or just restates the question without
      engaging the results: up to -5 across the whole notebook.

A6. CONVENTIONS: mu vs. r, mid vs. last trade, day-count tau
    - The risk-free rate r (never the underlying's real-world mu) is used in
      every pricing/Delta/implied-vol calculation; the bid-ask mid (not last
      trade) is the stated default quote source for every comparison, with any
      deviation justified; the day-count convention for tau is stated once and
      held consistent everywhere it affects sigma*sqrt(tau): no deduction.
    - One of the three conventions is violated in a single, otherwise-isolated
      spot: -3 here (plus any per-section correctness loss).
    - mu and r are conflated anywhere results are reported, or tau's
      convention silently changes between sections: -3, and flagged per A8.

A7. CODE HYGIENE
    - Reasonably organized; the notebook extends the Module 10/11
      black_scholes / greeks / implied_vol / simulate_hedge_pnl functions
      rather than reimplementing them from scratch or copy-pasting hedge-loop
      logic repeatedly where a parameterized function was clearly intended; no
      dead cells that error: no deduction.
    - Egregiously disorganized, or near-duplicated hedge loops where a
      function was clearly intended: -2.

A8. RED FLAGS (the "rookie mistakes" from the prompt) -- checked in context of
    the relevant section, deducted there, but flagged explicitly in feedback:
    - Confusing mu and r anywhere in pricing, Delta, or the hedge loop.
    - Using one strike's implied vol to price or hedge a materially different
      strike without acknowledging the smile (the exact failure Section 6
      quantifies).
    - Quoting "the market price" ambiguously -- not stating whether mid, bid,
      or ask is in use in a given comparison.
    - A day-count convention for tau that silently changes between sections.
    - Declaring a put-call-parity "arbitrage" that disappears once bid-ask
      spreads are properly subtracted (Section 2.2).
    - Delta-only hedging P&L reported with no acknowledgment of the
      uncompensated Vega exposure (Section 4/6).
    - Look-ahead bias: calibrating or selecting an implied vol using data from
      after the point in (real or simulated) time the hedge is being run,
      most specifically using a later day's implied vol in Section 4.2 instead
      of the contract's first available day.
    - Hedging P&L reported without transaction costs anywhere it's used to
      support a real recommendation (Section 5/7).

MAXIMUM TOTAL PART A DEDUCTION: -15 (A1 hard caps apply on top of this).
